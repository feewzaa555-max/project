## ภาพรวมโครงการ

โครงการนี้เป็นโปรแกรมจองตั๋วภาพยนตร์ที่พัฒนาด้วยภาษา Java ทั้งหมด ใช้เฉพาะไลบรารีมาตรฐานของ Java โดยไม่พึ่งไลบรารีภายนอก
หน้าจอแสดงผลสร้างด้วย Swing ส่วนข้อมูลทั้งหมดเก็บเป็นไฟล์ CSV ผู้ใช้ต้องสมัครสมาชิกและเข้าสู่ระบบก่อน จึงจะเติมเงิน เลือกรอบฉาย เลือกที่นั่ง และจองตั๋วได้

ความสามารถหลักของโปรแกรม

- สมัครบัญชีและเข้าสู่ระบบ โดยระบบจะแสดงข้อความแจ้งข้อผิดพลาดไว้ใต้ช่องที่กรอกไม่ถูกต้อง
- เลือกดูภาพยนตร์ที่เข้าฉายและรอบฉายของแต่ละวัน จองล่วงหน้าได้ 3 วัน นับรวมวันปัจจุบัน
- เลือกที่นั่งได้หลายที่นั่งในการจองครั้งเดียว โดยระบบจะแสดงที่นั่งที่ถูกจองไปแล้ว
- เติมเงินเข้ากระเป๋าเงินในโปรแกรม และใช้เงินจำนวนนั้นชำระค่าตั๋ว
- สมัครสมาชิกรายเดือนเพื่อรับส่วนลดค่าตั๋ว
- ดูประวัติการจองย้อนหลัง
- ปรับเวลาของโปรแกรมได้ตามต้องการ เพื่อใช้สาธิตกรณีที่รอบฉายเริ่มไปแล้ว โดยไม่ต้องรอเวลาจริง

ข้อมูลภาพยนตร์เก็บในไฟล์ `movies.csv` ในรูปแบบ `รหัส,ชื่อเรื่อง,ความยาว(นาที),ที่อยู่โปสเตอร์`

| M2 | Pacific Rim | 131 |
| M3 | Ghost Rider | 110 |
| M4 | Jurassic Park III | 92 |
| M5 | Blade Runner 2049 | 164 |

ตารางฉายเก็บในไฟล์ `schedule.csv` ในรูปแบบ `โรง,เวลาเริ่ม,รหัสภาพยนตร์` มี 3 โรง โรงละ 5 รอบต่อวัน และใช้ตารางเดียวกันทุกวัน

| โรง 1 | โรง 2 | โรง 3 |
|---|---|---|
| 10:00 M1 | 10:20 M3 | 10:40 M5 |
| 12:45 M2 | 12:30 M4 | 13:45 M1 |
| 15:20 M3 | 14:25 M5 | 16:30 M2 |
| 17:30 M4 | 17:30 M1 | 19:05 M3 |
| 19:25 M5 | 20:15 M2 | 21:15 M4 |

เงื่อนไขของรอบฉาย

- ภาพยนตร์ต้องจบก่อนเที่ยงคืนของวันเดียวกัน หากรอบใดจบเที่ยงคืนหรือหลังจากนั้น โปรแกรมจะแจ้งข้อผิดพลาดตอนอ่านไฟล์
- เมื่อถึงเวลาเริ่มฉายแล้ว จะจองรอบนั้นไม่ได้ และปุ่มรอบจะแสดงเป็นสีเทา
- รหัสรอบมีรูปแบบ `วันที่_Hโรง_เวลาเริ่ม` เช่น `2026-10-01_H1_1000` ใช้อ้างอิงรอบในไฟล์การจอง

## ราคา กระเป๋าเงิน และสมาชิก

### ราคาตั๋ว

ราคาตั๋วต่อที่นั่งคิดจากราคาปกติ 160 บาท บวกส่วนเพิ่มตามประเภทที่นั่ง ทุกโรงและทุกรอบใช้ราคาเดียวกัน

| ประเภทที่นั่ง | บุคคลทั่วไป | สมาชิก (ลด 10%) |
|---|---|---|
| ธรรมดา (แถว A ถึง E) | 160 บาท | 144 บาท |
| VIP (แถว F, บวกเพิ่ม 40 บาท) | 200 บาท | 180 บาท |

ตัวอย่าง การจองที่นั่ง A1 และ F7 รวมกัน ราคาปกติ 360 บาท หากเป็นสมาชิกจะชำระ 324 บาท

### กระเป๋าเงิน

- ผู้ใช้ที่สมัครใหม่มีเงินเริ่มต้น 0 บาท
- เติมเงินได้ครั้งละ 1 ถึง 5,000 บาท ไม่จำกัดยอดรวม
- ชำระเงินได้ไม่เกินจำนวนเงินที่มีอยู่

### สมาชิกรายเดือน

- ค่าสมาชิก 99 บาทต่อ 30 วัน ตัดจากเงินในกระเป๋า
- หากต่อสมาชิกก่อนหมดอายุ ระบบจะนับ 30 วันต่อจากเวลาหมดอายุเดิม วันที่เหลืออยู่จึงไม่สูญหาย
- หากสมาชิกหมดอายุแล้ว ระบบจะเริ่มนับ 30 วันใหม่จากเวลาที่สมัคร
- สถานะสมาชิกสิ้นสุดตรงตามเวลาหมดอายุ เช่น หมดอายุ 29/10 เวลา 06:00 เมื่อถึงเวลา 06:00 พอดีจะไม่ถือเป็นสมาชิกแล้ว

## กติกาการจอง

- จองได้เฉพาะรอบที่ยังไม่เริ่มฉาย
- ต้องเลือกอย่างน้อย 1 ที่นั่ง เลือกที่นั่งซ้ำกันไม่ได้ และเลือกที่นั่งที่ถูกจองแล้วไม่ได้
- ชำระเงินจากเงินในกระเป๋าทันทีเมื่อกดยืนยัน หากเงินไม่พอจะจองไม่ได้
- เมื่อจองแล้วไม่สามารถยกเลิกหรือขอคืนเงินได้ ดังนั้นไฟล์การจองจึงไม่มีช่องสถานะ แถวใดที่อยู่ในไฟล์ หมายความว่าที่นั่งเหล่านั้นถูกจองแล้ว
- รหัสการจองออกเรียงลำดับโดยอัตโนมัติ เป็น B1, B2, B3 และต่อไป
- ประวัติการจองแสดงรายการล่าสุดไว้บนสุด

ข้อความแจ้งข้อผิดพลาดที่เกิดจากการใช้งาน เช่น ที่นั่งถูกจองแล้ว เงินไม่พอ หรือรอบเริ่มฉายแล้ว เป็นภาษาไทย และนำไปแสดงบนหน้าจอได้ทันที

## รูปแบบไฟล์ข้อมูล

ไฟล์ทุกไฟล์เข้ารหัส UTF-8 และไม่มีบรรทัดหัวตาราง ไฟล์ `users.csv`, `accounts.csv` และ `bookings.csv` ไม่จำเป็นต้องมีมาตั้งแต่ต้น โปรแกรมจะสร้างให้เองเมื่อมีการบันทึกครั้งแรก

| ไฟล์ | รูปแบบ | ตัวอย่าง |
|---|---|---|
| `users.csv` | `ชื่อผู้ใช้,รหัสผ่าน` | `somchai,abc123` |
| `accounts.csv` | `ชื่อผู้ใช้,เงินคงเหลือ,เวลาหมดสมาชิก` (เว้นว่างหากไม่เคยเป็นสมาชิก) | `somchai,201,2027-10-29T06:00` |
| `bookings.csv` | `รหัสจอง,ชื่อผู้ใช้,รหัสรอบ,ที่นั่ง,ราคารวม,เวลาที่จอง` (คั่นที่นั่งด้วย `;`) | `B1,somchai,2026-10-01_H1_1000,A1;F7,324,2026-10-01T09:15` |

หากข้อมูลในไฟล์ผิดรูปแบบ โปรแกรมจะแจ้งชื่อไฟล์และเลขบรรทัดที่ผิด เพื่อให้แก้ไขได้ตรงจุด

## โครงสร้างของโปรแกรม

โปรแกรมแบ่งเป็นชั้นต่าง ๆ ตามหน้าที่ แต่ละชั้นเรียกใช้ชั้นถัดไปผ่าน interface จึงเปลี่ยนวิธีเก็บข้อมูลได้โดยไม่ต้องแก้ส่วนที่เรียกใช้

| แพ็กเกจ | คลาส | หน้าที่ |
|---|---|---|
| `model` | `User`, `Account`, `Movie`, `Showtime`, `Seat`, `SeatType`, `HallLayout`, `Booking` | เก็บข้อมูลและกฎของข้อมูลนั้น ทุกคลาสแก้ไขค่าไม่ได้หลังสร้าง |
| `repository` | `UserRepository`, `AccountRepository`, `BookingRepository`, `MovieRepository` | interface ที่ระบุว่าอ่านและบันทึกข้อมูลอะไรได้บ้าง |
| `repository` | `CsvUserRepository`, `CsvAccountRepository`, `CsvBookingRepository`, `CsvMovieRepository` | อ่านและเขียนข้อมูลจริงในไฟล์ CSV |
| `service` | `AuthService` | ตรวจและดำเนินการสมัครสมาชิกและเข้าสู่ระบบ |
| `service` | `MovieService` | จัดเตรียมรายการภาพยนตร์ วันที่จองได้ รอบฉาย และตรวจว่ารอบใดยังจองได้ |
| `service` | `AccountService` | เติมเงิน ชำระเงิน สมัครและต่ออายุสมาชิก |
| `service` | `BookingService` | ตรวจเงื่อนไขการจอง บันทึกการจอง ตัดเงิน และเรียกดูประวัติ |
| `service` | `PriceCalculator` | คิดราคาตั๋ว เป็นที่เดียวที่รู้ราคาปกติและส่วนลดสมาชิก |
| `service` | `AppClock` | นาฬิกากลางของโปรแกรม ตั้งเวลาเองสำหรับสาธิตและคืนกลับเป็นเวลาจริงได้ |
| `service` | `AppServices` | สร้างและรวม service ทั้งหมดเพียงครั้งเดียวตอนเปิดโปรแกรม ทุกหน้าจอใช้ชุดเดียวกัน |
| `exception` | `AuthError`, `AuthField`, `AuthFormException` | ข้อผิดพลาดของฟอร์มสมัครและเข้าสู่ระบบ ระบุได้ว่าต้องแสดงใต้ช่องใด |
| `gui` | `LoginFrame` | หน้าต่างสมัครและเข้าสู่ระบบ |

## หลักการออกแบบ

- **ข้อมูลแก้ไขไม่ได้ (immutable)** ใช้ `record` สำหรับข้อมูลเกือบทั้งหมด เมธอดที่ทำให้ค่าเปลี่ยน เช่น `Account.topUp` จะคืนอ็อบเจ็กต์ใหม่ ผู้เรียกจึงต้องนำค่าที่ได้กลับไปใช้ต่อ
- **ตรวจค่าตั้งแต่ต้นทาง (fail-fast)** ตรวจความถูกต้องของค่าใน constructor ข้อมูลที่ผิดจากไฟล์ CSV จะถูกพบทันทีที่อ่าน ไม่ลุกลามไปพังที่อื่น
- **ระบุสัญญาของแต่ละคลาส** มีคอมเมนต์ Abstraction Function, Representation Invariant และการป้องกัน rep exposure กำกับทุกคลาส พร้อมเมธอด `checkRep()` ที่ตรวจเงื่อนไขด้วย `assert` เมื่อรันด้วยตัวเลือก `-ea`
- **แยกหน้าที่ชัดเจน** model เก็บข้อมูล repository จัดการไฟล์ service รวมขั้นตอนการทำงาน และ gui แสดงผลเท่านั้น
- **พึ่งพา interface ไม่พึ่งพาคลาสจริง** service รับ repository ผ่าน constructor จึงทดสอบด้วย repository จำลองในหน่วยความจำได้โดยไม่ต้องสร้างไฟล์
- **ไม่ใช้ตัวเลขลอย** ค่าต่าง ๆ เช่น ราคา ส่วนลด ขนาดผัง และจำนวนวันของสมาชิก ตั้งชื่อเป็นค่าคงที่ไว้ที่เดียว หากต้องการเปลี่ยนจึงแก้เพียงจุดเดียว
- **ใช้นาฬิกาตัวเดียวทั้งโปรแกรม** ไม่เรียกเวลาจากเครื่องโดยตรง ผลทดสอบจึงไม่เปลี่ยนตามเวลาที่รัน และสาธิตได้สะดวก

## วิธีรันโปรแกรม

ต้องใช้ Java 16 ขึ้นไป เนื่องจากใช้ `record` ตัวอย่างคำสั่งด้านล่างให้ปรับตามโครงสร้างโฟลเดอร์จริงของโครงการ

```
javac -d out model/*.java exception/*.java repository/*.java service/*.java gui/*.java
java -ea -cp out gui.LoginFrame
```

ตัวเลือก `-ea` เปิดการตรวจ `assert` ซึ่งช่วยจับข้อผิดพลาดภายในคลาสระหว่างพัฒนา

## ความคืบหน้า

ส่วนที่พัฒนาเสร็จแล้ว

- คลาสข้อมูลทั้งหมดในแพ็กเกจ `model`
- ระบบสมัครและเข้าสู่ระบบ ทั้งส่วนตรวจกฎ (`AuthService`) และหน้าจอ (`LoginFrame`)
- ชั้นเก็บข้อมูลแบบ CSV ของผู้ใช้ บัญชี การจอง และภาพยนตร์
- ระบบหลังบ้านของภาพยนตร์ รอบฉาย กระเป๋าเงิน สมาชิก การคิดราคา และการจอง
- นาฬิกากลางและตัวรวม service (`AppClock`, `AppServices`)

ส่วนที่ยังต้องดำเนินการ

- ปรับ `LoginFrame` ให้รับ `AppServices` และเปิดหน้าหลักต่อจากการเข้าสู่ระบบ (ปัจจุบันยังสร้าง `AuthService` เองใน `main`)
- หน้าหลักสำหรับเลือกภาพยนตร์ วันที่ และรอบฉาย พร้อมแถบแสดงเงินและสถานะสมาชิก
- หน้าเลือกที่นั่งและสรุปราคา
- หน้าเติมเงินและสมัครสมาชิก
